# AI / 协作者工作约束

> 本文件是硬约束的完整版。`AGENTS.md` 只保留摘要与索引，冲突时以本文件为准并同步修正 `AGENTS.md`。

## 1. 判定标准

**这个文件是不是“仓库产物”（源码、配置、构建脚本、正式文档、CI 定义）？不是 → 必须放 `ai_agents/`。**

包括但不限于：计划、方案、调研笔记、任务拆解、改动说明、验证记录、临时脚本
（`.bat` / `.ps1` / `.sh` / `.py`）、运行日志、构建日志、截图、测试数据、导出的中间产物、
解包出来的源码副本。

## 2. `ai_agents/` 子目录

| 目录 | 放什么 | 生命周期 |
| --- | --- | --- |
| `plan/` | 计划、方案、设计草稿、任务拆解、调研结论 | 任务结束后保留或自行归档 |
| `impl/` | 实施记录、改动说明、验证步骤、回归清单 | 可随任务结束清理 |
| `scripts/` | 一次性 / 临时脚本（排查、批处理、数据修复） | 用完即删，或按 §4 转正 |
| `logs/` | 运行日志、构建日志、调试输出 | 定期清理，禁止提交 |
| `output/` | 报告、图表、导出文件等交付中间物 | 交付后清理 |
| `tmp/` | 中间文件、缓存、解压产物、实验副本 | 随时可删 |

## 3. 命名

```
YYYYMMDD-<简短英文或拼音>-<描述>.md     例：20261125-构建失败排查.md
YYYYMMDD-<主题>.log                     例：20261125-gradle-build.log
YYYYMMDD-<用途>.bat|sh|py               例：20261125-清缓存.bat
```

## 4. 转正规则

临时内容被证明**长期有价值**时，才允许移出 `ai_agents/`：

| 内容 | 去处 |
| --- | --- |
| 可复用脚本 | `scripts/`；属于构建流程 → `gradle/*.gradle.kts` 或 `buildSrc/` |
| 对外使用文档 | `docs/src/doc/docs/` |
| 开发文档 / 规范 | `docs/dev/` |
| 每次必读的硬约束 | `AGENTS.md` |

移入后必须同步更新对应索引（`AGENTS.md` 或 `docs/README.md`）；**未经转正的文件不得进入版本库**。

## 5. 文档写在哪

| 位置 | 放什么 | 进站点 |
| --- | --- | --- |
| `docs/src/doc/docs/` | 安装、使用、功能、版本记录等**对外**文档 | ✅ |
| `docs/dev/` | 架构、构建、脚本说明、发布流程、开发约束 | ❌ |
| `AGENTS.md` | 每次必读的硬约束 + 索引，保持简短 | ❌ |
| `docs/TODO.md` | 待办 | ❌ |

判断口诀：读者是“用软件的人” → `docs/src`；读者是“改仓库的人/AI” → `docs/dev`。

## 6. 禁止事项

- ❌ 在仓库根目录或模块目录下新建 `.bat` / `.ps1` / `.sh` / `.log` / `*.md` 草稿、截图、`*.db`、解压目录、临时副本
- ❌ 把日志、临时脚本、本地数据写进 `src/` 或模块根目录
- ❌ 把需要长期保留的文件放进 `build/`（构建清理会删除）
- ❌ 修改 `.gitignore` 放行 `ai_agents/`（该目录仅供本地使用）
- ❌ 在 `src/` 里写“临时验证代码”后忘记删除

## 7. 提交前检查清单

1. `git status --short` 只应出现源码 / 配置 / 构建脚本 / 正式文档等仓库产物
2. 每个新增文件都能回答“它属于哪个模块、承担什么职责”；答不上来 → 移入 `ai_agents/`
3. 暂存区没有 `build/`、日志、临时脚本、本地数据库、截图、`__pycache__/`
4. 改动了两边重复的版本（`ben-manes-versions`、`commons-compress`）→ 两处已同步
   （见 `versioning.md`）
5. 改动了目录职责、模块依赖或构建约定 → 同步更新 `AGENTS.md` 与 `docs/dev/` 对应文档
